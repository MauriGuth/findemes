# Phase 4 — manual test checklist (tickets, AI entries, chats)

**Before starting**

- **Bucket (Cloudflare R2)**: dash.cloudflare.com → R2 → Create bucket `findemes-tickets` (private, no public access) → Manage R2 API Tokens → Create token "Object Read & Write" for that bucket. Railway → API → Variables: `S3_ENDPOINT` (`https://<account id>.r2.cloudflarestorage.com`), `S3_REGION=auto`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`. Optional: a lifecycle rule deleting objects older than 400 days.
- **Telegram**: in Telegram talk to @BotFather → `/newbot` → name "Findemes" → a username ending in `bot`. Railway: `TELEGRAM_BOT_TOKEN` (the token), `TELEGRAM_BOT_USERNAME` (without @), `TELEGRAM_WEBHOOK_SECRET` (`openssl rand -hex 32`), `API_PUBLIC_URL=https://findemesapi-production.up.railway.app`. The deploy log shows `telegram.webhook_set`.
- **WhatsApp (optional, Meta)**: developers.facebook.com → app type Business → add WhatsApp → a phone number → permanent token from a System User. Webhook URL `https://findemesapi-production.up.railway.app/chat/whatsapp`, verify token = `WHATSAPP_VERIFY_TOKEN`, subscribe to `messages`. Railway: `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_DISPLAY_NUMBER`.
- The deploy shows the Pre-deploy step with migration `20261015120000_phase4_chat_links`.
- **New APK needed** (camera and gallery are native): run the `Mobile build` workflow with profile `preview` and install it over the old one.

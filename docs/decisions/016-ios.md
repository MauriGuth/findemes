# 016 — iOS: Shortcuts, Apple Pay and builds

Date: 2026-10-14 · Status: accepted (delegated by Mauricio: "completá todo el plan")

## Context

iOS does not let an app read other apps' notifications (no equivalent of Android's NotificationListenerService), so automatic capture as in Phase 2 is impossible. ADR 011 set the iOS channels: forwarded email (working since Phase 3), a Shortcuts template for bank SMS and Apple Pay, quick manual entry (Phase 1 and the AI entry of Phase 4), and a share extension. Mauricio uses Android; building for iOS needs his Apple Developer account (US$99/year).

## Decisions

- **`POST /ingest/shortcut`**, authenticated with the device's ingest token (ADR 009), the same pipeline as Android: encrypted `RawEvent` with channel `IOS_SHORTCUT` (30 days), security codes dropped, templates of the source named in the sender or the text, Claude when none matches. Two kinds:
  - `message`: the text of an SMS (or any message an automation can read) plus its sender.
  - `apple_pay`: the fields of the Shortcuts "Transaction" trigger (amount as the iPhone formats it, merchant, card name). Apple does not say debit or credit: "débito" in the card name means DEBIT, otherwise CREDIT, and the movement waits in Pendientes (confidence 0.8). The source comes from the card name when it names a bank.
    Idempotent per device, content and minute (a Shortcut can fire twice).
- **The key does not age out on iPhone**: on Android the app rotates it every 30 days and it dies at 60, but a Shortcut cannot be updated by the app, so an expiring key would break the automation silently. iPhone keys (Device.platform IOS) are revoked only by logout, account deletion or generating a new one from the app. The key only authorizes `/ingest/*`, so a leaked key can add movements to Pendientes but read nothing.
- **App**: Ajustes → "Atajos del iPhone" (iOS only) generates the key (shown once), and explains the two automations step by step. No `.shortcut` file is distributed: Apple requires signed shortcuts shared through iCloud links, which need Mauricio's account; the link can be added to that screen later.
- **Builds**: `app.config.ts` declares `usesNonExemptEncryption: false` (standard HTTPS only, no export paperwork) and the Face ID usage text. The `Mobile build` workflow takes `platform: ios`; the first iOS build must be run once interactively (`npx eas-cli@latest build --platform ios --profile preview`) so EAS creates the certificates and provisioning profile with Mauricio's Apple account, then it works from GitHub. TestFlight: profile `production` + `eas submit`.
- **Share extension: postponed.** Sharing a photo or screenshot to Findemes needs a native extension target (iOS) and an intent filter with native reading (Android); the available library (`expo-share-intent`) patches native projects and must be verified on a real device before it ships. Until then, the "+" → "Sacale foto al ticket" → "Elegir de la galería" path covers the same need.

## Consequences

- iPhone users get automatic capture only for what an automation can see: SMS (banks that send them), Apple Pay, and forwarded email. Bank app push notifications are out of reach on iOS.
- Without Mauricio's Apple Developer account nothing iOS can be built or tested; the API side is covered by e2e tests.
